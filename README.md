# ● ドットカフェ モバイルオーダーシステム

文化祭限定のドットカフェをイメージした、スマートフォンから注文できるレトロポップなWebアプリケーションです。

お客さんはスマートフォンから注文し、スタッフは注文状況・メニュー・在庫を管理できます。

## まずはここから：かんたんな使い方

### お客さま：注文する

1. お店の注文ページをスマートフォンで開きます。
2. 欲しい商品の「＋ カートへ」を押します。商品カードに「SOLD OUT」や「売り切れ」と出ている商品は注文できません。
3. 画面下の「カートを見る」を押し、数量と合計金額を確認します。「＋」「−」で数量を変え、「削除」で商品を外せます。
4. 「この内容で注文する」を押します。画面に出た注文番号を控えてください。
5. 注文完了画面の「注文状況を確認する」を押すと、受付済み・調理中などの状況を確認できます。同じブラウザーのタブを開いている間は、ページを移動しても注文状況を確認できます。

### スタッフ：注文を受けて、メニューを管理する

1. 注文ページ右上の「スタッフの方はこちら」を押します。
2. 管理者から共有されたスタッフ用合言葉でログインします。合言葉はサーバー側で照合され、有効期間の間だけ管理機能を使えます。
3. 「注文管理」で商品・数量・金額を確認し、注文ごとの選択欄を「受付済み」→「調理中」→「受け渡し待ち」→「受け渡し済み」と進めます。お客さまの注文状況にも反映されます。
4. 「商品・在庫」で新しい商品を登録するときは、商品名・説明・価格・絵文字・在庫を入力して「メニューを追加」を押します。
5. 登録済みの商品は「編集」を押すと入力欄に内容が入ります。変更後に「変更を保存」を押してください。
6. 在庫数を **0** にすると売り切れ表示になります。一時的にメニューから隠したい商品は「販売停止」、再び売るときは「販売を再開」を押します。商品を削除しないので、過去の注文記録は残ります。
7. 「注文履歴」では「受け渡し済み」にした注文を確認できます。
8. 作業が終わったら「ログアウト」を押します。

**注意：** Firebaseの設定前は画面の見た目を確認するプレビューです。注文の確定やスタッフログインは使えません。お店で実際に使うには、下の「管理者：最初に一度だけ行う設定」を先に完了してください。

### 管理者：最初に一度だけ行う設定

Firebase Consoleとコマンド操作が必要です。順番に一度設定した後、日々の注文・メニュー管理はスタッフ画面から行います。

1. Firebaseプロジェクトを作り、Webアプリを登録して、表示された設定値を [`js/firebase-config.js`](./js/firebase-config.js) に貼り付けます。
2. Firestore Databaseを作成します。最初の商品カタログは、管理画面への初回ログイン時に登録されます。
3. Cloud Functionsを使うためBlaze料金プランを設定します。**利用量によって料金が発生する可能性があります。** 料金・無料枠を確認してください。
4. 16文字以上のスタッフ用合言葉を、ソースコードやチャットに書かず、Firebase Functions Secretとして登録します。
5. Functions・Firestoreルール・Hostingを公開し、事前確認ログインと当日の注文・在庫更新を確認します。

Firebase設定を受け取る場合は、Webアプリの設定JSONだけを使ってください。サービスアカウントの秘密鍵、パスワード、支払い情報はGitHubやチャットへ登録しないでください。

### 画面だけ先に見たいとき

Firebaseを設定しなくても、商品カードやスタッフ画面の見た目をプレビューできます。プロジェクトのフォルダーでPowerShellを開き、次を実行します。

```powershell
python -m http.server 8000
```

ブラウザーで `http://localhost:8000` を開きます。スタッフ画面は右上のリンクから開けます。Firebase設定前はログイン・注文の確定・商品の保存はできません。サーバーを止めるときは、PowerShellで `Ctrl+C` を押します。

## 🔐 セキュリティ方針

- 店員用管理画面は認証を必須にする
- Firestore Security Rulesでアクセス権限を制限する
- 在庫確認と注文確定は信頼できるサーバー側処理で行う
- クライアントから送信された価格や合計金額をそのまま信用しない
- Firebaseの秘密鍵や認証情報をGitHubに公開しない

## 🚀 ローカル環境構築と実行手順

このアプリは、Firebase 未設定時のプレビューと、Firebase を有効化した本番運用の両方で動かせます。

### 1. 必要な環境

- Node.js 22 LTS
- npm
- Python 3
- Firebase CLI（本番デプロイ用）

### 2. 依存関係をインストールする

```bash
cd /Users/yuki/Desktop/2年I科/文化祭/cafe-website-main
npm install --prefix functions
```

Cloud Functions 用の依存関係が入ります。Node.js 22 以外では Firebase SDK の互換性で不具合が出る可能性があるため、22 系を推奨します。

### 3. ローカルで画面を確認する

Firebase 設定なしでも、見た目の確認はできます。

```bash
cd /Users/yuki/Desktop/2年I科/文化祭/cafe-website-main
python3 -m http.server 8000
```

ブラウザーで `http://localhost:8000` を開いてください。

- `index.html`: お客さま向け注文画面
- `admin.html`: スタッフ向け管理画面

注意: Firebase 未設定の状態では、注文確定・ログイン・商品保存は動作しません。

### 4. Firebase を使う場合の準備

本番運用を行うには次を設定してください。

1. Firebase Console でプロジェクトを作成する
2. Web アプリを登録して `js/firebase-config.js` に設定値を入れる
3. Firebase Functions Secretにスタッフ用合言葉を登録する
4. Firestore Database を作成する
5. Cloud Functions を使うために Blaze プランを確認・有効化する
6. Firebase CLI でFunctions・Firestoreルール・Hostingをデプロイする

```bash
npx firebase-tools login
npx firebase-tools deploy --only functions,firestore:rules,hosting --project cafe-website-4367f
```

### 5. 実行の順番

1. まずはローカルプレビューで画面を確認する
2. Firebase の設定値を `js/firebase-config.js` に入れる
3. 16文字以上の合言葉をSecretとして登録する
4. Firestore と Cloud Functions をデプロイする
5. スマートフォンから注文テストを行う

これで「画面確認」から「実運用テスト」まで進められます。

## AWS 版再設計方針（Firebase から切り替える場合）

Firebase の課金が必要なため、AWS Academy の無料枠を活用して、費用を抑えた構成に切り替える方向を検討しています。実運用では「無駄な課金を避け、文化祭当日に確実に動くこと」を最優先にします。

### 目標

- Firebase の月額・従量課金を避ける
- AWS Academy の無料枠を活用する
- 文化祭当日の運用を安全に行う
- チーム内で実装と運用の責任を分担しやすくする

### 推奨構成

- フロントエンド: HTML / CSS / JavaScript（そのまま使用）
- 配信: Amazon S3 + CloudFront
- API: EC2 + Apache + PHP
- DB: MariaDB
- 認証: PHP セッションベースの管理者ログイン
- 注文受け取り: 注文番号 + ランダムな5桁合言葉で管理

### 変更理由

- Firebase は Cloud Functions と Blaze プランが必要で、料金が発生しやすい
- AWS Academy の無料枠で EC2 と MariaDB を使う方が、短期イベント向けにコストを抑えやすい
- PHP と MariaDB は、学校の開発環境と相性がよく、チームで運用しやすい

### 変更対象

- `js/firebase.js` を `js/api.js` に置き換える
- Firebase Cloud Functions の役割を PHP API に置き換える
- Firebase Authentication を PHP セッション認証に置き換える
- Firestore を MariaDB に置き換える
- `functions/` 配下の処理を EC2 上の PHP API に移行する
